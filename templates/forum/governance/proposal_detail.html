{% extends "forum/governance/base_governance.html" %}{% load i18n %} {% comment %} One proposal: who tabled it, what it says, where it stands, and what may happen to it next. Two deliberate choices: 1. The PROPOSER is rendered through `governance_services.public_profile` — organisation, category, declared interests. The template is handed a dict with exactly three keys, so it could not print an e-mail address even if someone later added one to the model. 2. The transitions offered are the ones the DOMAIN would accept from this caller (`available_transitions`), not every edge of the lifecycle. A screen that offers a button the service will refuse teaches people to distrust the screen. The form posts a target; the service re-checks it, because a form is an interface and an interface can be bypassed. The decision is rendered as `.outcome`: a WORD at title size with a state rule, and the motivation underneath. There is no « approuvé » that could be read as an administrative decision — a commission retains or sets aside a proposal, it decides nothing about anyone's situation. {% endcomment %} {% block page_title %}{{ proposal.title_fr }}{% endblock %} {% block meta_description %}{% translate "Proposition du Forum permanent : texte, état et décision motivée." %}{% endblock %} {% block portal_header %} {% include "components/page_header.html" with title=proposal.title_fr eyebrow=proposal.commission.name_fr %} {% endblock %} {% block governance_content %}
