Pastilles

{% for kind in badge_kinds %} {% include "components/badge.html" with label=kind kind=kind only %} {% endfor %}

Sept kind hérités, cinq registres : neutral, info et primary sont tous neutro. Les deux registres qu'aucun kind ne produit, les deux modificateurs et les deux tailles, écrits à la main pour que les sept formes soient sous les yeux :

nullo sigillo indicatif sans registre chip--s chip--l

« Sans registre » est une pastille dont la valeur n'est pas connue de chips.py : filet pointillé, pour qu'elle se voie et se corrige. Le sigillo n'est jamais interactif ; l'indicatif n'a pas de corps et porte, sur le site, la mention visible « à titre indicatif ».

{% comment %} This block is the most important paragraph on the page. `success` and `info` render in the SAME three colours, which looks like an obvious defect when the two sit side by side — and the obvious repair is forbidden. The rule lives in static/css/tokens.css, in docs/design/DESIGN_SYSTEM_2026.md §4.3 and in the domain's list of outcomes; it does NOT live next to the CSS classes, whose names invite exactly the wrong fix. So it is written here, at the one place where somebody is about to make that mistake. {% endcomment %}

Pourquoi success n'est pas vert, et ne le sera pas

Aucune couleur ne signifie jamais « approuvé ». Une étape achevée est transmise ou close : un fait sur le dossier, pas un verdict. C'est la même raison pour laquelle l'issue eligible n'existe pas dans le modèle de domaine — cette plateforme n'approuve rien, et rien dans l'interface ne doit pouvoir se lire comme une approbation. La règle est écrite dans static/css/tokens.css et dans DESIGN_SYSTEM_2026.md §4.3.

La pastille porte donc son sens trois fois sans couleur : le mot, le style du filet (plein · tireté · double · pointillé) et sa géométrie (1, 3 ou 4 px ; un filet de clôture sous conforme, deux filets qui barrent rifiuto). Le mot est toujours dans l'encre du chapitre ; la couleur ne vit que dans la marque, et conforme n'en a pas. Le registre vient de l'enum, en Python (apps/core/chips.py), jamais du mot : closed est un fait sur un dossier de documents et un vide sur une édition du forum.
