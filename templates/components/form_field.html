{% load i18n ile_core ile_forms %}{% comment %} THE FIELD — the one partial of the form system (V5.12 W2, lane B; DECISIONS §5). Every form of the product renders its fields through it; enquiries/partials/form_field.html and allauth/elements/field.html are thin adapters of the same anatomy, and the newsletter's consent is this partial too. Contract: include with `field` (a BoundField). Optional: `help` (override help text), `consent` (True → consent styling for the mandatory, never pre-checked checkbox), `label_lang` (the label's language when the locked text is the fallback; default `field.field.label_lang`), `glyph` (the leading glyph; default by input type — e-mail `at-sign`, phone `phone`; "none" for none). THE ANATOMY (DECISIONS §5.2): the label, 14/20 at 500, always visible above the control — never a floating label — followed by «facultatif» when the field is optional: the minority is marked, the required fields carry no asterisk (§5.3), their controls keep `required` (Django writes it, and `aria-required` with it). Then the control plate (52 px public, 44 px console; v5/field.css) with a leading glyph slot and a trailing status slot (the error's circle-alert, the read-only lock, and from the inline check the warning or the confirmed value's check — a status is never colour alone: the edge, the mark and the words). Then the help line, the character counter of a textarea with a limit, and the message row (`.form-field__msg`, aria-live polite): the server's errors at load, the inline check's after (static/js/src/fieldcheck.js, on blur, then on input once the field has been touched; never blocking typing). The row opens from 0fr to 1fr in 160 ms, the edge changes in 120 ms, nothing shakes (M10). Django 5.2 writes aria-invalid and an aria-describedby pointing at `{{ field.auto_id }}_helptext` and `{{ field.auto_id }}_error`: the help and error elements use exactly those ids (docs/ACCESSIBILITY.md §6). The server's messages for the inline check are the server's own (`data-msg-*`: required, type, max/min length, low/high), so the two never disagree. Hidden widgets and the honeypot render bare (no label), the honeypot inside its off-screen wrapper. The other kinds are their own components, the same anatomy: a radio or checkbox group → components/choice_cards.html; a date → components/date_field.html (day / month / year, no calendar grid); a number → components/number_field.html (the − / + stepper). A select of more than 15 options carries `data-combobox` (static/js/src/combobox.js enhances it; without script it is the native select). THE LABEL ROW'S SLOT (design V5 «Il varco», W2-B). A field whose form sets `help_beside_label` (the sign-in's password) has its help at the end of the label's row: the `form-field__aside`, WRITTEN AFTER THE CONTROL — from the keyboard the address is followed by the password, never by a link — and placed in the label's row by apps/accounts/static/accounts/entrance.css. THE NEW PASSWORD'S CHECKLIST (V5.15 W3, lane B; DECISIONS §5.11): a password the person creates (autocomplete="new-password", not its confirmation) shows the validators' own rules as a checklist in place of Django's help list (`ui.rules`, apps/core/templatetags/ile_forms.py); fieldcheck.js marks each rule it can verify as it is typed — the length, not only digits — and says the count once, politely, when the typing pauses; the rules only the server can judge are one quiet sentence under the list, without marks (round 1). No strength meter (§5.11). Paste is allowed; the show / hide control stays.
