## Violazioni dei vincoli non negoziabili

1. PAGE-MODE CONTRACT (shadows). DESIGN_SYSTEM_V2.md §7: `| DENSE | fascicolo, liste, tabelle, back-office | ... | Vietato: ombre, vetro, reveal |`. §2 further restricts level-2 shadow to `--shadow-2` **solo in hover**. Spec line 128 gives `.cf-sheet` `--shadow-2` at rest, line 129 gives `.cf-sheet--acting` `--shadow-3`, line 167 the inspector `--shadow-2`, line 172 `.cf-actionbar` `--shadow-3`. Line 67 makes this the explicit premium thesis ('premium si ottiene con ombre di ruolo multistrato ... che qui non sono usate'). They are not used because this page class forbids them.

2. PAGE-MODE CONTRACT (photography). DESIGN_SYSTEM_V2.md §6: 'Altre fotografie **solo su IMMERSIVE e RICH**'. Spec §4.B lines 106-117 places `demarches-ecriture-{480,960,1440}.webp` at 176px as the centrepiece of a DENSE page. This is the spec's answer to the owner's 'not enough images' and it is not available on this surface.

3. PAGE-MODE CONTRACT (reveals + scroll-linked + loop). MOTION_SYSTEM.md §4: 'Le pagine RICH ne hanno al massimo uno dei due; **STANDARD, DENSE e LEGAL nessuno**' (no ambient loop, no scroll-indexed object); §7 DENSE Vietato includes 'reveal'. Spec line 235 `cf-band-compact` is a scroll-linked object; line 236 `cf-rail-locate` is an `inView` staggered opacity+translateX reveal; line 244 `cf-skeleton` is a loop.

4. MOTION DURATION SET. Constraint: 4 durations {120,180,240,320} + one immersive trace 600-900ms; MOTION_SYSTEM §1 'Nessun altro numero', and the only permitted loop is `--motion-ambient` >= 20 000ms, **lineare**. Spec line 244 `cf-skeleton` = '1200 ms in loop' on curve `--ease-standard`: a duration outside the token set, a loop 17x shorter than the floor, and an eased loop where the rule says linear.

5. SEVEN MOTION FUNCTIONS. MOTION_SYSTEM §0: 'Ogni animazione dichiara **una** funzione fra sette' (orientamento, gerarchia, causalità, stato, feedback, profondità, delizia). Spec line 238 `cf-row-settle` declares its Funzione as **'layout'**, which is not one of the seven — it is the name of the §2 *family*, whose declared function is 'causalità'.

6. ONE INTERACTIVE ACCENT. DESIGN_SYSTEM_V2 §1.3 rule 1: '`--accent` ... **Nessun titolo, icona o sfondo lo usa**'. Spec §4.E line 138: 'solo la versione in vigore porta il filetto `--accent`' — an accent fillet on `.cf-plate`, a decorative icon inside `<td aria-hidden="true">` (line 220). Secondarily line 150/188 invents `--cf-drag: #E3F1F2` as an accent-tinted *ground* when `--accent-wash: #d9eef0` already exists in tokens.css and is the sanctioned form.

## Lacune (ciò che l'implementatore dovrebbe inventare)

1. BAND COLLAPSE HAS NO MECHANISM. Line 102 says `.cf-band` 'si comprime allo scroll da 176 px a 56 px', but line 235 lists the animated properties as only `translateY`+`scale` and `opacity` of the photo plus `translateY` of the facts — none of which changes the band's own `block-size`. Animating `height` is on MOTION_SYSTEM §2's 'mai' list. The implementer must invent the construction (grid-template-rows? two stacked layers? `animation-timeline: scroll()` on a custom property?). Line 121's rail offset `top: calc(var(--cf-band-compact) + 16px)` is only correct *after* the collapse; the transitional state, where the band is still 176px, is undefined and the rail will sit under it.

2. `transform-origin: inline-start` IS NOT VALID CSS. Stated at line 153 and again at line 239, and the RTL section (line 268) rests on it: 'la barra si risolve da sola perché la sua origine è `inline-start`'. Verified in headless Chromium: `CSS.supports('transform-origin','inline-start')` === false, the declaration is dropped, and the computed value falls back to `50% 50%`. As written the upload bar grows from the centre outwards in both directions, in FR and AR alike. Required instead: `transform-origin: left` with `[dir="rtl"] { transform-origin: right }`.

3. SCRIM IS PHYSICAL, TEXT IS LOGICAL. Line 110 fixes the scrim as `linear-gradient(90deg, var(--mid-1) 0 38%, ...)` while all text uses logical properties. In `dir="rtl"` the opaque 38% stays on the left and the text moves to the right, onto the transparent end — which silently voids line 111's guarantee that 'Tutto il testo vive nel 38 % pieno' and with it every contrast figure in §4.B. §6 (line 266-268) lists what mirrors and does not include the scrim.

4. TABLE → GRID ABOVE 768 IS UNSPECIFIED AND INVERTED. Line 134: 'Sotto 768 resta una `<table>` reale ... Sopra 768 la riga diventa una griglia'. This inverts DESIGN_SYSTEM_V2 §9.4 ('Tabella reale **sopra** 768 con `caption`, `scope`') and contradicts the written contract in apps/portal/static/portal/portal.css:379 ('Above 768 the table is a real table and the header is read normally'). The snippet at 219-223 keeps `<tr>`/`<th scope="row">`, so `display:grid` on `<tr>` would strip the row/cell roles that portal.css deliberately preserved. The spec names no `role="table"/"row"/"cell"` replacement and does not say whether to use grid or `table-layout: fixed` + `<col>`. The implementer must choose, on the most important surface in the spec.

5. `.st--action::after` HAS NO POSITIONING CONTEXT. Lines 192-194 use `position: absolute; inset-block-start: 50%; inset-inline-start: 50%` on the pseudo-element, but never declare `position: relative` on `.st--action`. As written the 44px touch target is placed against the nearest positioned ancestor, not the chip, and the 2.5.8 claim at line 256(c) fails.

6. `content-visibility: auto` WITHOUT `contain-intrinsic-size`. Lines 242 and 292 apply it to every `.cf-sheet` below the fold and to the closed inspector. With no intrinsic size the scrollbar and page height thrash as sheets enter the viewport — which also undermines the scroll-linked band and the '0 layout' claim at line 290.

7. `<dialog>` FOR THE STATE TRANSITION HAS NO NO-JS PATH. Lines 164-165 replace the inline `<select>` (templates/cases/detail.html:100, posting to `cases:set_item_status`) with a `.btn--secondary` opening a native `<dialog>`. A `<dialog>` cannot be opened without `showModal()`, so with JS off a role-permitted legal action becomes unreachable — against 'server-rendered templates + progressive enhancement', and against DESIGN_SYSTEM_V2 §9.8 which prescribes 'cambio di stato come **form a pagina** con conferma'. It is also unspecified whether there is one dialog per row or one shared dialog whose `action` URL is rewritten.

8. `.st` TYPE IS UNDEFINED. Line 190-192 gives display, gap, `min-block-size`, padding, radius, ground, fill, fillet and a 14x14 svg — but no `font-size`, `font-weight`, `font-family`, `letter-spacing` or `text-transform`, while line 269 (`:lang(ar) .st { text-transform: none }`) implies uppercase. The chip it replaces (static/css/register.css:702-717) is 13px/600/uppercase/`--track-folio` with its own `:lang(ar)` reset. The implementer must re-derive the type.

9. `SPRING_SETTLE` IS DOCUMENTED BUT NOT IMPLEMENTED. Line 238 calls it; MOTION_SYSTEM §1 defines it as `{stiffness:260, damping:30}`; static/js/src/motion.js only re-exports `spring` and defines `reducedMotion`/`withMotion`. The constant has to be added.

10. ANATOMY SILENTLY OVERRIDES §9.1 AND §9.3. Line 97 proposes rail 264 / 1fr / inspector 344; §9.1 says 224 / 1fr / 320. Line 99 proposes a 52px horizontal strip at 768-1023; §9.1 says 36px below 1024. Line 102 puts the band on `--mid-1`; §9.1 puts the case band on `--mid-2`. §9.3 specifies the rail as '`<ol>` di N segmenti a tutta larghezza **sopra** le colonne ... **Verticale sotto 1024**' — the spec inverts it (vertical beside the columns above 1280, horizontal at 768-1023). None of these overrides is acknowledged or argued.

11. JS BUDGET IS MIS-ADDED. Line 284 claims '≈ 31 KB su 45' = case-file.js 5.2 + Motion 26. The spec's own measure (casefile_measure_desktop.json `scripts`) shows the page also loads `js/head.js` and `js/main.js`; measured gzip: 206 B + 5,309 B + shell.js 613 B = ~6.1 KB. Real page total ≈ 37.3 KB. Still inside 45, but the margin is ~7.7 KB, not 14 — and that is the margin any later addition will be judged against.

## Segnali di «cheap / generico / default»

1. THE PHOTO-BEHIND-A-SCRIM BAND IS THE MOST TEMPLATED 'PREMIUM' MOVE OF THE LAST FIVE YEARS. §4.B is a stock hero image with a gradient overlay and white text — every SaaS dashboard header from 2020 onward. It is also the spec's only spectacle, and line 116 fades it to `opacity: 0` at the first pixel of scroll, so it pays nothing after one screen. An owner who called the current work 'unmemorable' will recognise this shape instantly.

2. `2px dashed` DROPZONE. Line 149 is the default Tailwind/shadcn upload affordance, unchanged. The spec spends a full 21st.dev row (candidate 9) arguing that the empty state *is* the dropzone, then draws the same dashed rectangle everyone draws.

3. THE CHIP IS SHADCN `Badge` WITH THE SERIAL NUMBERS FILED OFF. `border-radius: 2px`, `inline-flex`, pale tinted ground, dark same-hue text, 1px fillet, 14px leading icon (lines 190-192) is the default `secondary`/`destructive`/`outline` badge. The `::after` touch-target trick is lifted verbatim from candidate 2's `pointer-coarse:after:min-h-11` and the spec says so. The four grounds are green/amber/red/grey — the generic semantic triad the spec itself rejected in UI-UX-Pro-Max query 3 (line 63) as violating the single-accent rule.

4. TWO OF THE FOUR 'NEW' COLOURS ARE THE COLOURS ALREADY ON SCREEN. `--st-pending-fg #5E4B14` is rgb(94,75,20) and `--st-err-fg #8F1D1D` is rgb(143,29,29) — the exact values §1.5 (lines 39-40) criticises in the current build. `--st-ok-bg #DCEFE4` is byte-identical to the existing `--ok-100`, `--st-err-bg #F6DEDC` to `--err-100`, `--cf-field-line #55646B` to `--ink-3`. §4.T presents this as a new palette with computed ratios; it is mostly a re-badging, and it leaves a second green and a second red sitting beside `--ok-700`/`--err-700` for someone to drift into.

5. THE BUTTON SPINNER CONTRADICTS THE SPEC'S OWN REJECTION. Line 75 refuses candidate 1 for '`animate-spin` come loop permanente'; line 201 then specifies '`tratto rotante 900 ms`' as the `.btn--primary` loading state. (DESIGN_SYSTEM_V2 §10 does prescribe 'loading con spinner a tratto + testo', so it is sanctioned — but the spec cannot use 'permanent rotation' as a disqualifier and then ship one without a word.)

6. THE ONE GENUINELY DISTINCTIVE IDEA IS UNDER-SPECIFIED. The `case-glyphs.svg` sprite (8 species plates with a folded corner, 8 state glyphs, a MA→IT frontier mark) and the 5-tick meter are the only things here that could not have come from a component library — and they get one sentence each (lines 136-137, 115-116) with no drawing rules, no stroke weight, no grid, against the icon contract in §6 (proprietary set, 1.5px stroke, 20px). The premium of this page lives or dies on that sprite and the spec hands the implementer nothing to draw it from.
