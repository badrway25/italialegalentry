# 21ST.DEV COMPONENT MATRIX — merged, final (V5)

**Italy Legal Entry™ · Executive Creative Director · 27 September 2026 · status PROPOSED — revised after the red team** (`RED_TEAM.md`; §3.1 below lists the rows it changed, and rows 114–122 are the nine types it added).
Merged from the five family curations (`council/21st_nav-shell.md`, `21st_hero-public.md`, `21st_primitives.md`, `21st_forms-docs.md`, `21st_platform-domains.md`), plus the 21st lookups of the motion (`MOTION.md` §14.6) and mobile (`MOBILE_UX.md` §1.4) lanes. The matrix is organised by the **V5 component registry** (122 types, `DESIGN_SYSTEM_V5.md` §11), not by family: where two or three families curated the same thing (the drawer, the segmented control, the skeleton, the document card, the journey), their rows are merged into one type and their candidates deduplicated by 21st id.

**Method of the merge.** The council's 77 matrix rows were parsed from the five reports (`scratch/ecd/parse_matrix.py` → `matrix_rows.json`), the 600 candidate-register rows likewise (`parse_registers.py` → `register_rows.json`, 544 distinct candidates), and each council row was mapped to one or more registry types (appendix A). The **FINAL SELECTED** column is the ECD's decision; where it differs from the council's, §3 lists the change and `CREATIVE_DIRECTION_V5.md` §21/§23 gives the reason. Generated by `scratch/ecd/gen_matrix_md.py`; the numbers in §1 are computed, not typed.

**What «adapt» means here.** No 21st component is installed or copied. A selected candidate contributes a *mechanism* (a gesture, a state model, an accessibility model, a timing) that is rewritten in Django templates, V5 tokens, native elements and, where needed, a small ES module or Motion 13.4.1. The author's colours, radii, shadows, springs, icons and runtime dependencies never enter (the conversion filter, `CREATIVE_DIRECTION_V5.md` §1.5). If any snippet were ever ported literally, its licence would have to be checked first (not audited: nothing is ported).

## 5. The React-island question (route C) — answered per candidate

A React island would be justified only if **all** of these held: (1) the interaction cannot be built with server-rendered HTML + CSS + ≤ ~4 KB of vanilla JS or Motion; (2) its state is genuinely client-side and complex (not a form, not a list, not a disclosure); (3) the island stays within the public JS budget (≤ 45 KB gz per page, ≈ 40.5 used by V5) and adds no long task > 50 ms under CPU ×4; (4) it works under `script-src 'self'` and `style-src 'self'` without injected styles; (5) the page is complete and usable without it (progressive enhancement); (6) it is accessible at least as well as the native alternative.

| Candidate interaction | Would a React component help? | Criterion that fails | V5 answer |
|---|---|---|---|
| Liquid-metal hero button (#10443, #21563) | its wrapper is React | 3 (100.6 KB gz for metal-fx + react-dom), 4 (injected `<style>`) | CSS «Bordo d'oro» |
| Command palette «Aller à…» (#27378, cmdk-based) | cmdk is React | 1 (a native `<dialog>` + combobox + listbox in < 4 KB) | route A, dynamic import on first use |
| Upload «Dépôt» (#27137, #28271) | React state for a file list | 1, 2 (the state is a list of rows the server renders; XHR events are plain JS) | route A, `depot.js` |
| Mega-menu section swap and height morph (#21349, #31509 — Base UI / motion/react) | viewport morph | 1 (Motion `animate` on a measured transform) | route A + B |
| Notification centre (#27135, framer-motion) | list + tabs | 1, 6 (its row is a `role=button` wrapping buttons — nested interactive) | route A |
| Toast manager (#24297, Base UI) | a toast stack | 1 (server-rendered from Django messages; CSS custom properties for the stack) | route A |
| Data table (TanStack family) | sorting, selection | 1, 2 (sort as server links; selection only for staff bulk, native checkboxes) | route A |
| Kanban (#29221, #29372) | drag state | domain rule (no drag of a governed state) | rejected; state lanes, route A |
| PDF preview | a viewer | 4, security (`frame-ancestors`, `worker-src`/wasm) | rejected; the piece page's `<article>` in a drawer |
| Journey path animation (#24528, #24556 — motion/react) | path drawing | 1 (native scroll-driven CSS, 0 bytes of JS on the home; one WAAPI in the console) | route A |
| Charts / KPI dashboards | charts | domain rule (no percentages, no scores) | rejected |

**Result: route C = 0.** No interaction in V5 meets the six criteria. React is not added to the stack; the owner's instruction not to rewrite the app to Next.js/React stands on the merits, not only on the order.
